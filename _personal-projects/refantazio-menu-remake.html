Phase 2: UI Architecture

Layered UI architecture showing how gameplay state, input, dependency injection, and UI systems interact through clean separation of responsibilities and event‑driven communication.

Architectural Priorities & Approach

1. Ensure deterministic, debuggable transitions

Approach: Drive all menu and HUD navigation through explicit state machines, enabling predictable transitions and async-safe execution via UniTask.

2. Minimize cross‑system coupling

Approach: Use Dependency Injection via a centralized Object Resolver to prevent UI elements from referencing external systems directly, and ensure external systems never reach into UI internals.

3. Build a generic, extensible UI framework

Approach: Use composable UI abstraction (PageSection, HUDWidget) and event‑driven communication to support unlimited screens and nested UI structures without modifying core systems.

Phase 3: Data Architecture

A structured data‑flow architecture showing how authored ScriptableObjects generate runtime models that expose observable properties for UI binders to reactively display and update.

Architectural Priorities & Approach

1. Establish a deterministic, fully debuggable data pipeline

Approach: Use ScriptableObject‑driven authoring to ensure all runtime values originate from validated definitions. Designers work with safe, structured templates, while runtime instances remain deterministic and fully traceable.

2. Maintain strict separation between authoring, runtime data, and UI layers

Approach: Runtime values are represented through a dedicated ObservableProperty<T> model, while UI layers consume data exclusively through IPropertyProvider. This prevents cross‑system coupling and eliminates hidden dependencies.

3. Provide reactive, event‑driven runtime models

Approach: ObservableProperty<T> exposes type‑safe change notifications via events, enabling any system—UI, gameplay, or meta‑systems, to react cleanly and predictably to data changes without polling or manual synchronization.

4. Enable a generic, extensible UI binding framework

Approach: A designer‑facing PropertyBinder component allows any UI element to bind to any observable property directly in the editor. No custom code is required, enabling a fully reactive UI pipeline that scales to any number of HUD elements or menu screens.

5. Empower designers with a scalable, code‑free content workflow

Approach: ScriptableObject templates and standardized property providers allow designers and integrators to work with established data types—characters, items, skills, archetypes, etc, without engineering intervention. The system remains safe, extensible, and future‑proof.

Phase 4: Integration

With the core architecture in place, I moved on to building the actual HUD elements, menu pages, and their nested sections. To standardize this process, I developed a set of tools that streamline the creation and configuration of these UI elements.

Key Integration Components

Asset Pool Manager: A centralized pooling system designed to efficiently manage reusable game objects in Unity. It automatically loads all PoolableObject prefabs from configured Resources paths, initializes dedicated pools for each type, and ensures they always maintain a minimum spare capacity. The manager supports single and batch retrieval, type‑safe or reflection‑based access, and clean return‑to‑pool workflows.

By reusing inactive instances instead of instantiating and destroying objects at runtime, this system significantly reduces allocation spikes, improves frame stability, and eliminates common pooling pitfalls such as missing pools, inconsistent parenting, or improperly reset objects. Its type‑driven architecture ensures predictable behavior, easy extensibility, and is boilerplate-free for developers integrating new pooled assets.

UI Object Generator From Pool: an abstract, data‑driven UI list builder that uses an AssetPoolManager to generate interface elements from pooled objects. It clears old content, pulls and initializes new items from data, and tracks all active UI instances for retrieval or removal. The class also provides a generation event and ensures returned objects are fully reset and recycled.

Its generic, data‑driven design allows any poolable UI element type to be generated consistently without custom boilerplate, while maintaining clean lifecycle management and predictable behavior across different UI systems.

UI Object Selecter: an abstract controller for cycling and managing selectable UI elements. It hooks into a PageSection to handle navigation events, supports reversed cycling, and tracks the current selection and index. The class exposes selection‑change events, updates its selectable list, and provides utilities for selecting specific items, selecting all, or applying predicates that control which elements are eligible.

Its generic, interface‑based structure delivers consistent, centralized selection behavior across UI types with minimal custom logic.

UI List Selection Section: an abstract PageSection that links pooled UI generation with selection handling. It resolves its data model and asset pool at runtime, initializes a UIObjectGeneraterFromPool, and keeps a UIObjectSelecter synchronized with generated items. The section can remove the current selection and delegates UI creation to an overridable method.

It centralizes list creation, selection state, and dependency resolution, making dynamic, data‑driven UI sections easier to build and maintain.

Property Binder: an abstract component that binds runtime data to UI or gameplay elements through an ObservableProperty. It resolves the provider and property, subscribes to change events via minimal reflection, applies the initial value, and forwards updates to the most specific Apply overload implemented by subclasses. The binder also handles clean unbinding to avoid stale event hooks. A custom editor was created for this tool to be easily usable by designers and integrators for plug and play data binding.

Its dynamic, type‑safe binding approach removes boilerplate and supports flexible, reactive systems that adapt cleanly to changing data.
