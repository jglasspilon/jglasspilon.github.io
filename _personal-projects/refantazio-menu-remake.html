Phase 2: UI Architecture

Architectural Priorities:

  • Minimize cross‑system coupling by preventing UI components, widgets, or pages from referencing external systems directly, and by ensuring external systems never reach into UI internals.
  • Ensure all transitions are deterministic, predictable, and fully debuggable, regardless of whether they originate from gameplay state changes, input events, or UI navigation.
  • Design a generic, extensible UI framework capable of supporting an open‑ended number of menu screens, HUD contexts, and nested UI sections without requiring modifications to core systems.

Approach:

  • Dependency Injection via Object Resolver: All high‑level services (input, game state, UI) are resolved through a centralized Object Resolver, eliminating downward coupling and keeping all core level systems interface‑driven for flexibility.
  • State-Machine-Driven Navigation: Menu flow and HUD context are governed by explicit state machines, ensuring predictable transitions, clean debugging, and fully asynchronous execution via UniTask.
  • Event-Driven Communication: State changes propagate through C# events, enabling reactive, decoupled communication where systems broadcast intent without knowing who listens.
  • Composable UI Components: Interfaces like IPageSection and IHUDWidget standardize behavior for nested UI elements, enabling complex compositions without special‑case handling.

Phase 3: Data Architecture

Architectural Priorities:

  • Establish a deterministic, fully debuggable data pipeline where all runtime values originate from validated definitions.
  • Maintain strict separationbetween authoring, runtime data, and UI layers, ensuring no cross‑system coupling or hidden dependencies.
  • Provide reactive, event‑driven runtime models that expose data changes cleanly and predictably to any system that needs them.
  • Enable a generic, extensible UI binding framework capable of supporting any number of HUD elements, menu screens, or contextual UI states without modifying core systems.
  • Empower designers with a safe, scalable content‑creation workflow that supports an open‑ended number of data types (characters, items, skills, archetypes, etc.) without requiring further engineering intervention.

Approach:

  • ScriptableObject‑Driven Authoring: Gameplay data is authored as ScriptableObject templates, giving designers a code‑free workflow while ensuring validated, deterministic runtime instances.
  • ObservableProperty Runtime Model: A custom ObservableProperty<T> class provides individual type‑safe values and built-in change notification using events. The transmission of these are standardized through the IPropertyProvider implementation for a clean reactive data layer.
  • Generic Property Binding: A designer‑facing PropertyBinder component lets any UI element bind to any designer specified observable property with no extra code, done completely through the editor, enabling a fully reactive UI pipeline that scales effortlessly.
  • Composable UI Components: Interfaces like IPageSection and IHUDWidget standardize behavior for nested UI elements, enabling complex compositions without special‑case handling.
